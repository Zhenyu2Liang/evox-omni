# live 办理稳定性验收

分支：`genesis/agent_841944ee`，基线：`af647b8`。本次无 schema 变更，不需要重置或重新 seed 开发数据库。

## 实现

- 每个 live 模型请求默认 30 秒截止时间，包含响应流停滞；最多一次传输重试，过长的服务端等待要求直接失败。`LLM_REQUEST_TIMEOUT_MS` 可配置为 1000–120000 毫秒。
- 尚未启动写工具、计划或授权时，遇到暂时性故障或仅口头回复，可保留查询结果和原用户请求补做一次规划。有效澄清、产品拒绝与认证/协议错误不强行重试。
- 写入、计划或授权已开始时，保留结果与原入口，不自动重放。恢复耗尽后给出阶段说明，最新回复可提供“重试规划”；新消息开始后旧按钮退出，快速连续点击由同步发送锁拦截。
- 生成门控动作或计划后不再请求模型播报；live 确认后的结果直接根据可信业务结果展示和保存，所属 DAG 仍由原执行器继续。模型不可修改金额、收款人、权限或执行结果。

## 真实前端与 DeepSeek

使用生产构建、实际浏览器页面和隔离的 `prisma/live-recovery-browser-*.db`。临时本地代理将正常请求转发到已配置的真实 DeepSeek 服务；故障注入只返回明确的 HTTP 503 错误，不伪造模型成功回复。

| 前端流程 | 实际结果 |
| --- | --- |
| 规划服务不可用 → 刷新 → 点击重试 | 连续注入 4 次 HTTP 503，覆盖两次模型尝试及其传输重试；停止自动恢复后仍有按钮，刷新保留；此时授权、计划、转账均为 0，活期仍 ¥23,580.00 |
| 恢复后转账 ¥123.45 | DeepSeek 生成张伟的 YELLOW 确认卡；本人点击确认后余额 ¥23,456.55，恰一条对应 DEBIT；确认前后上游请求计数均为 2 |
| 大额转账 ¥2,000.13 | 错码不新增流水，余额不变；正确码后余额 ¥21,456.42；仅一笔入账 |
| 预算 → 大额转账 → 仅成功后提醒 | 预算节点成功；¥30,000.01 因余额不足失败；提醒节点 skipped，无该提醒授权/记录，余额仍 ¥21,456.42，既有两笔转账保留 |
| 两笔申购 | 货币基金 ¥100.25、稳健理财A ¥1,000.13 分别验证；两条对应投资 DEBIT，余额依次 ¥21,356.17 → ¥20,356.04，计划 success；刷新不重跑 |

故障注入与真实模型正常业务分开验证。浏览器操作没有通过直接调用银行写接口替代；余额、流水和持久化状态作为额外交叉核对。开发库与 `.env.local` 的 SHA256 在验证前后相同；没有打印密钥。

## 限制

外部模型可继续出现故障。限时针对单个模型请求，整个多工具对话可涉及多个请求。仅口头回复的恢复采用有限业务词表，不保证所有自然语言表达；它只选择是否补做规划，不替模型填参数或授予权限。本次不是多实例压力或跨浏览器验收。
