# 万象柜坊 EvoX Omni 部署与使用说明

本说明用于竞赛本地部署与功能演示。系统使用虚构用户、模拟账户和模拟银行交易，不连接真实资金。

## 1. 运行环境

| 项目 | 要求 |
| --- | --- |
| Node.js | 22.19.0 及以上版本 |
| 包管理器 | pnpm 12.3.4 |
| 数据库 | SQLite，初始化时自动创建文件，无需单独安装数据库服务 |
| 浏览器 | 近期版本 Chrome 或 Edge；自动浏览器验收需要系统 Chrome |
| 模型 | mock 模式无需密钥；live 模式需要可用的模型服务、网络及 API Key |

所有命令在解压后的项目根目录执行。可用以下命令核对环境：

```sh
node --version
pnpm --version
```

尚未安装 pnpm 时执行：

```sh
npm install -g pnpm@12.3.4
```

## 2. 首次部署

### 2.1 创建本地配置

在项目根目录创建 `.env.local`，写入以下内容：

```dotenv
LLM_MODE=mock
DATABASE_URL="file:./competition-demo.db"
DEMO_USER_ID=user_liming
```

该配置使用独立的竞赛演示库，实际文件位于 `prisma/competition-demo.db`。源码包中没有数据库文件时，执行初始化即可生成。

已有 `.env.local` 时只修改需要的字段，不覆盖已有密钥。复用已有数据库时，将 `DATABASE_URL` 指向对应文件，并跳过重新加载初始数据的命令。终端中已有同名环境变量时，进程环境优先；初始化前需确认实际目标数据库。

### 2.2 安装与初始化

```sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:push
pnpm db:seed
```

警告：`db:seed` 会重建演示用户的业务数据。仅在首次初始化或明确重建时执行；已有数据需要保留时，先按第 7 节备份。

### 2.3 启动网页

```sh
pnpm dev --hostname 127.0.0.1 --port 3000
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)，进入 AI 助手。页面使用固定演示用户，无需注册或登录。

访问 [运行状态](http://127.0.0.1:3000/api/health)，可检查服务状态与模型模式。

### 2.4 使用生产构建演示

在开发服务终端按 `Ctrl+C` 停止后，执行：

```sh
pnpm build
pnpm start --hostname 127.0.0.1 --port 3000
```

开发模式与生产模式选择一种运行，避免端口冲突。

## 3. 使用真实模型

需要演示自由表达、多轮澄清和复杂任务时，使用 live 模式。mock 模式只用于预置场景和自动化回归。

在 `.env.local` 中替换或补充以下字段，保留原数据库配置：

```dotenv
LLM_MODE=live
LLM_PROVIDER=deepseek
LLM_MODEL=deepseek-flash
DEEPSEEK_API_KEY=YOUR_DEEPSEEK_API_KEY
```

将 `YOUR_DEEPSEEK_API_KEY` 替换为本机可用密钥，再重启银行服务。通过运行状态接口确认 `llmMode` 为 `live`。

说明：真实模型只负责语言理解与工具规划，银行业务仍在本地模拟数据库执行。API Key 不应写入提交材料或公开仓库。

首次进入时可查看使用引导。关闭后不再自动弹出，也可从“使用帮助”重新打开。侧栏底部可切换界面语言，以及浅色、深色或跟随系统的外观。

当日累计转账已超过阈值时，小额转账也会要求验证。信息不足时，按助手追问补充对象、金额或赎回口径。

### 5.1 确认、验证与结果

1. 核对操作面板中的对象、金额、账户和权限等级。
2. 黄色操作点击确认，红色操作按提示输入 `123456`。
3. 等待结果卡更新。
4. 到对应业务页或“操作记录”核对状态。

验证码应输入操作面板，不在普通聊天中发送。连续 3 次错误可能锁定操作并触发熔断；可到安全中心解除限制，但原锁定操作不会自动继续。

### 5.2 任务控制与人工接管

任务卡片提供暂停、继续、取消和符合条件的重试。取消后，可回退未使用预算和未执行定时记录，已入账交易保留。

人工接管在开发者模式下的“人工核对（演示）”中操作，可登记原因、说明和后续处理结论。人工核对不能代替用户确认或验证码验证。

## 6. 微信与后台任务

### 6.1 微信接入

保持银行 Web 服务运行。在第二个终端执行：

```sh
pnpm weixin:login
```

扫描二维码并在手机确认。登录完成后执行：

```sh
pnpm weixin:start
```

发送“查询我的活期账户余额”验证收发。二维码过期时重新运行登录命令。通道仅支持绑定用户的文字私聊，登录令牌不随作品公开提交。

银行服务地址默认为 `http://127.0.0.1:3000`。更改端口时，同步修改 `.env.local` 中的 `WEIXIN_BANKING_URL`。

常用微信命令如下，将操作编号替换为机器人实际返回的编号：

```text
/帮助
/待办
/确认 操作编号
/验证 操作编号 123456
/取消 操作编号
```

普通聊天中的“确认”不会授予执行权限。微信与网页使用同一银行服务时共享业务数据，页面操作完成或刷新后可读取最新状态。

### 6.2 恢复与定时任务

需要后台持续检查中断运行时，在另一个终端启动：

```sh
pnpm agent:worker
```

只检查一次，可执行 `pnpm agent:recover`。检查到期任务使用 `pnpm scheduler:tick`，启动 Web 不会自动启动后台循环。

业务演示时间固定为 **2026 年 9 月 25 日 12:00，UTC+08:00**。“今天”“本月”和转账累计按该业务日期计算；认证有效期与熔断冷却按实际时间计算。

先在对话中创建提醒：“在 2026 年 9 月 25 日 12:01 提醒我检查账单”。再在本机执行指定时间的到期检查：

```sh
pnpm scheduler:tick --now "2026-09-25T12:02:00+08:00"
```

随后到定时任务页查看提醒。定时付款到期后仍需满足确认和验证要求，不会因时间到达自动绕过权限。

## 7. 数据备份与恢复

演示操作会写入数据库，关闭浏览器或重启服务不会自动还原。需要保留当前状态时执行：

```sh
node scripts/db-backup.mjs
```

命令备份当前配置的数据库，输出文件位置位于 `logs/db-backups/`，并生成对应说明文件。

恢复时按以下步骤操作：

1. 在各终端按 `Ctrl+C`，停止 Web、微信和后台进程。
2. 保留当前数据库及备份。
3. 将选定快照复制为新的数据库文件，例如 `prisma/restored-demo.db`。
4. 将 `.env.local` 的 `DATABASE_URL` 改为 `file:./restored-demo.db`。
5. 使用匹配的程序版本重新启动服务。

新文件名应未被其他数据库使用，避免与旧的 SQLite 临时文件混用。

明确需要清除操作并重建演示数据时，可在停止服务、完成备份后运行 `pnpm db:reset`。该命令不是普通启动步骤。

## 8. 测试与常见问题

### 8.1 自动化检查

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm exec tsx tests/e2e/acceptance.e2e.ts
```

测试使用隔离数据库，浏览器脚本需要系统 Chrome。自动化回归默认使用 mock 模型，不能替代 live 模式下的前端验收。

### 8.2 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 源码包没有数据库或提示表不存在 | 首次运行先完成数据库生成、结构同步和初始数据加载 |
| 页面仍显示旧模型模式 | 修改 `.env.local` 后重启 Web 服务，再查看运行状态 |
| 端口 3000 已被占用 | 关闭旧 Web 服务后再启动，避免重复运行同一端口 |
| 卡号、余额与本说明不同 | 说明使用初始化资料；已有库的数据随演示操作变化，以页面当前记录为准 |
| 补办后不知道新卡号 | 在办理结果中选择“查看卡号”，原挂失卡不会恢复 |
| 短信一直没有收到 | 本项目不发送短信，使用操作面板中的模拟验证流程 |
| 网页与微信显示的数据不同 | 核对微信指向的银行地址及 Web 服务使用的数据库，再刷新页面 |
| 定时提醒未触发 | 核对演示时间、任务状态与到期检查是否已执行 |
