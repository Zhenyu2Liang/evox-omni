# 微信通道

微信通道使用 `pi-weixinbot@1.0.5` 的 iLink 协议模块。
通道把文字消息交给现有 Banking Agent HTTP 接口。
模型、业务权限、确认、验证码、审计和回执复用 Web 流程。
无需安装或运行 OpenClaw。

## 启动

先按[开发指南](development.md)准备应用。
已有演示数据库时，不必重新播种。
模型模式由银行服务的配置决定。
使用真实模型时，在 `.env.local` 配置 `LLM_MODE=live`、模型和密钥。

终端 1 启动银行服务：

```sh
pnpm dev
```

终端 2 登录微信，再启动收消息进程：

```sh
pnpm weixin:login
pnpm weixin:start
```

使用微信扫描终端二维码，并在手机确认。
二维码图片另存为 `logs/weixin-login.png`。
登录命令完成后，收消息进程才会启动。
启动信息会显示银行服务实际使用的 `live` 或 `mock` 模式。

打开微信中的机器人对话，发送“查询我的活期账户余额”。
正常收到回复后，再测试需要确认的业务。
首次登录、微信客户端兼容性和真实消息收发需要手机参与。
取得二维码不代表已完成微信联通。

## 确认与验证

可直接用自然语言查询或提出业务请求。
待确认业务回复包含服务端操作编号和操作详情。
核对金额、收款人和风险等级后，使用显式命令：

| 命令 | 作用 |
| --- | --- |
| `/帮助` | 查看通道命令 |
| `/待办` | 展示当前演示账户的待处理操作及真实状态 |
| `/确认 操作编号` | 确认指定操作；红色操作继续等待验证码 |
| `/验证 操作编号 六位验证码` | 为已确认的红色操作提交验证码 |
| `/取消 操作编号` | 取消指定待处理操作 |
| `/恢复操作 操作编号` | 请求服务端核对并恢复原操作，不创建新业务 |
| `/任务` 或 `/任务 任务编号` | 查看多步任务、节点状态和关联确认入口 |
| `/暂停 任务编号`、`/继续 任务编号` | 控制多步任务的执行 |
| `/重试 任务编号`、`/取消任务 任务编号` | 重试失败任务或取消后续步骤 |
| `/回退记录 任务编号` | 撤回可撤销的预算、定时记录；不撤销已入账交易 |
| `/定时任务`、`/检查到期` | 查看计划与通知，或执行一次真实时间的到期检查 |

普通聊天中的“确认”不构成执行授权。
验证码命令不会转发给模型，也不保存消息正文。
通道只接受已向绑定用户展示过的操作编号。
错误验证码、累计风险升级和熔断仍由银行服务处理。
模拟验证码和银行功能边界见[项目 README](../../README.md)。

### 验证失败与锁定回复

回复只由服务端的权威字段生成：`status`、`code` 和 `failure`。
第一段恒为状态块，写明操作编号和状态。

第 1、2 次验证码错误时，操作仍为 `awaiting_mfa`。
此时回复保留验证入口，并给出剩余次数：

```text
操作编号：A-1001
状态：等待验证码
继续验证：/验证 A-1001 六位验证码

验证码错误。还可尝试 2 次。
```

第 3 次错误后操作进入锁定终态。
锁定回复固定为 4 段：

```text
操作编号：A-1001
状态：已锁定

该操作已锁定，无法继续验证或执行。原因：验证码错误次数已达上限。请在安全中心解除限制后重新发起操作。

当前状态：该操作已锁定，不再提供验证码入口，也不会执行。

解除方式：请在网页安全中心解除限制；解除后需要重新发起这笔操作，系统不会自动执行原操作。
```

这 4 段依次是状态块、锁定词条、入口撤销说明和解除方式。
本轮还有事件或任务文本时，追加为第 5 段。

`继续验证：/验证 …` 只在状态为 `awaiting_mfa` 时出现。
锁定回复不出现这一行，也不暗示可以再次提交验证码。

次数耗尽时，顶层 `code` 仍是 `CIRCUIT_OPEN`。
具体原因由 `failure.code` 的 `MFA_LOCKED` 和 `failure.reason` 的 `mfa_attempts_exhausted` 表示。
`failure` 同时携带 `attemptsUsed`、`attemptsLeft` 和 `maxAttempts`。
只有 `attemptsLeft` 进入剩余次数文案。
字段含义见[安全设计](security.md#结构化安全失败)。

对锁定操作发送 `/确认`、`/验证`、`/取消` 或 `/恢复操作`，服务端都返回锁定结构。
此时 `code` 为 `CIRCUIT_OPEN`，`failure.reason` 为 `mfa_session_locked`。
微信渲染“安全验证已锁定。请在安全中心查看状态。”，不出现验证码入口。
账户已熔断、本操作尚未锁定时，服务端返回 `circuit_open` 并同时锁定该操作。
微信同样渲染这一句提示。

`/待办` 不再列出锁定操作。
锁定操作不新建验证码挑战，也不执行业务。

### 重试与重发

操作仍在 `awaiting_mfa` 时重复发送 `/验证`，复用同一验证码挑战。
剩余次数沿用原记录，不重置。
挑战过期或操作参数变化时，服务端重新签发验证码并重置剩余次数。
此时回复说明已重新生成验证。

已锁定的操作重复投递或刷新消息，回复仍是锁定结构。
锁定状态不会回到 `pending` 或 `awaiting_mfa`，也不重建验证码挑战。

任务停在锁定操作上时，`/继续` 和 `/重试` 会被服务端拒绝。
微信回复为 `MFA_LOCKED` 的公开拒绝文案，任务状态保持原样。
被锁定的节点不会重新执行。

### 验证码入口的撤销

服务端的安全拒绝事件会撤销该操作的确认和验证入口。
撤销后，后续回复不再出现该操作的确认或验证提示。
已结算的操作同样不再展示确认或验证入口。
撤销只影响微信侧的展示，不修改服务端状态。

### 公开文案

微信不自行拼接安全文案。
全部拒绝和失败提示经 `channels/weixin/presentation.ts` 的 `channelText` 交给[公开文案](../../lib/public-text.ts)。
`securityNotice` 只按服务端字段选择词条。
`blockReason`、`__SECURITY_BLOCK__` 载荷、原始 JSON 和异常堆栈都不进入微信消息。
判定规则见[安全设计](security.md#对外文案收口)。

### 解除限制后的微信表现

解锁入口和规则见[安全设计](security.md#解除安全限制)。
解锁只清除账户熔断和失败计数，原操作保持锁定。
成功响应中 `lockedActionsReopened` 恒为 `false`。
解锁不为锁定操作补发验证码入口，也不续期其验证码挑战。
解除限制后必须重新发起同一笔业务，并在网页或微信重新确认。

Web 与微信共用固定演示账户和对话。
微信发起的操作可在网页查看和处理。
网页发起的待处理操作可先通过 `/待办` 查看。
核对展示的详情后，才能使用微信命令确认。
处理中或待核对记录不会被说成“尚未执行”，也不会展示重复确认入口。
未知结果只提示核对，不声称已成功或资金未变。
网页或微信控制任务后，下一轮对话会读取当前任务状态。
历史消息中的等待状态不能代替当前已取消或已暂停状态。

## 业务覆盖

自然语言请求使用同一套银行工具。
结构化卡片转成微信文字，不依赖模型再叙述一次。

| 业务 | 微信支持的交互 |
| --- | --- |
| 账户、联系人、账单 | 余额、流水、消费分类、异常交易和资产总览 |
| 转账 | 按联系人或手机号发起，核对详情，按实际风险确认或验证 |
| 理财 | 产品列表与对比、持仓、申购、全额或部分赎回及结算回执 |
| 卡片 | 状态与限额查询、分类消费限额、临时锁卡与解锁、正式挂失与补办 |
| 虚拟卡 | 申请、绑定活期账户、消费及剩余月限额展示 |
| 订阅代扣 | 查询、开启或关闭续费提醒、取消订阅 |
| 预算 | 登记预算并显示“不冻结资金”的记录边界 |
| 多步任务 | 计划、各节点状态、确认入口、暂停、继续、取消、失败重试和记录回退 |
| 定时任务 | 创建、查询、检查到期、读取提醒通知和处理到期付款确认 |

定时检查沿用网页“检查到期任务”的行为。
微信进程不会隐式启动全账户的调度循环，也不会自动批准到期付款。
需要定期后台检查时，另行配置[调度入口](scheduled-tasks.md#部署入口)。
当前微信通知以主动查询或检查到期时回复，不承诺无人值守的到点推送。

新建全新实体卡、注销卡片、联系人编辑、本人交易标记、
人工接管和开发者维护仍由对应网页入口处理。
微信通道不增加模型原本不具备的银行写权限。

## 配置与状态

可在 `.env.local` 设置以下运行选项：

```dotenv
WEIXIN_BANKING_URL=http://127.0.0.1:3000
WEIXIN_STATE_DIR=.local/weixinbot
```

银行接口地址限本机回环地址。
微信通过出站长轮询接收消息，不需要开放入站端口。
银行服务换端口后，调整 `WEIXIN_BANKING_URL`。
通道与银行服务运行在同一台电脑。

```sh
pnpm weixin:status
pnpm weixin:login --force
pnpm weixin:logout
```

`status` 只报告本地登录缓存，不证明微信会话仍有效。
缓存过期时用 `login --force` 重新扫码。
`logout` 清除本地凭据和绑定，不代替微信客户端的账户管理。
退出登录、重新扫码前，先用 Ctrl+C 停止收消息进程。

令牌和绑定保存在 `.local/weixinbot/state.json`。
`.local/`、二维码和测试日志均被 Git 忽略。
该目录依赖当前操作系统账户的文件访问权限。
不要将令牌文件复制进源码、模型上下文或报告。

## 消息与权限边界

- 只接受登录结果中的扫码用户，不采用“首个发消息者自动绑定”。
- 群聊、陌生人、机器人回声和不完整消息不会进入模型。
- 目前支持文字；图片、文件和语音不交给模型识别。
- 单个进程串行处理消息，同一状态目录使用独占进程锁。
- 消息编号绑定银行请求编号，重复投递不再生成新一轮业务。
- 回复先保存到本地回复队列，发送失败时重发相同 `client_id`。
- 本地保留最近 2000 条已处理回复。银行请求本身仍使用稳定请求编号。
- 这是一名扫码用户访问一个共享演示账户的通道，不是多人银行身份系统。

通道不加载 `pi-weixinbot` 的默认编码扩展入口。
因此不向银行模型增加 shell、文件操作或任意收件人发送工具。
通道只导入上游的微信协议模块，并固定向已绑定发件人回复。
上游旧版 Pi peer dependencies 被标为可选，银行运行时仍使用项目的 Pi 1.2。

仓库为上游包维护 2 处补丁：
保留 uint64 消息编号精度；发送接口即使 HTTP 200，也检查微信业务错误。
补丁由 pnpm 锁文件和 `patches/pi-weixinbot@1.0.5.patch` 固定。

## 测试

```sh
pnpm exec vitest run tests/unit/weixin-channel.test.ts tests/unit/weixin-presentation.test.ts tests/unit/weixin-lock-presentation.test.ts tests/integration/weixin-protocol.test.ts
pnpm exec tsx tests/e2e/weixin-live.e2e.ts
```

第一条验证绑定、去重、显式授权、状态持久化、上游协议和锁定回复文案。
第二条调用真实模型及银行服务，并用 Chrome 检查网页状态。
该测试每次创建全新的隔离数据库，微信端使用本地协议服务器。
因此第二条不能替代“手机发消息并收到回复”的真实微信验收。
结果写入 `logs/weixin-live-acceptance.json` 和 `logs/weixin-live-acceptance-<runId>.json`，失败时退出码非 0。

设置 `WEIXIN_LIVE_EXTENDED=1` 后运行第二条命令，
还会检查查询、理财、卡片、订阅、预算、定时分发和任务控制。
归档搜索和取消后对话状态也在扩展测试范围内。
扩展测试只在新建测试库中把一条提醒设为到期，
不向 HTTP 接口传入测试时钟，也不修改微信演示库。

真实微信验收：扫码登录后，测试余额查询、小额转账待确认、
确认执行、大额操作错码拒绝、正确验证和取消。
同时核对网页操作状态、账户余额及流水。
