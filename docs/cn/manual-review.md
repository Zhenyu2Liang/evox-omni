# 人工处理

`/manual` 提供持久化人工处理入口。处理人可以暂停自动推进、登记说明和决定后续处理。
人工说明不会修改余额或补造交易。

## 处理流程

1. 打开“人工处理”。
2. 选择任务或独立操作。
3. 填写转人工原因。
4. 提交接管请求。
5. 等待在途命令到达安全检查点。
6. 填写核对说明。
7. 选择处理结论。

任务候选包括待执行、运行、暂停、待确认和失败状态。
独立操作候选包括有明确失败结果的操作，以及需要人工核对的操作。
原因长度为 5 至 1000 个字符，结论说明长度为 5 至 2000 个字符。

接管请求立即保存。运行中的计划进入暂停状态。
此前已取得执行权的命令可以完成，并保存原执行回执。
接管后，系统停止认领后继节点和新的授权执行。

## 接管状态

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| `human_review_requested` | 在途命令尚未结束 | 等待安全检查点 |
| `operator_controlled` | 系统已停止自动推进 | 登记说明并选择结论 |
| `resolved` | 人工记录已关闭 | 查看处理结论 |

服务端计算接管状态和按钮权限。隐藏页面按钮不能替代服务端检查。

## 处理结论

| 结论 | 条件 | 结果 |
| --- | --- | --- |
| `stop` | 在途命令已结束 | 取消未执行步骤和未执行授权 |
| `resume` | 任务已暂停或待确认，且没有失败节点或未知结果 | 释放人工控制，保留原图与原授权 |
| `retry` | 任务失败，且有明确的未提交证据 | 重试失败节点及其依赖节点 |

已成功节点和已入账交易始终保留。
恢复待确认任务后，用户仍需决定原操作。
授权过期、认证过期和风险升级按当前安全规则处理。

失败写节点必须有明确失败结果。系统核验没有提交回执后，才允许重试。
未决确认、活动执行、已提交结果和未知结果都会阻止重试。
重试写节点仍经过确认与认证流程。

`needs_reconciliation` 表示金融结果不明。处理人只能登记说明并结束自动处理。
关闭人工记录后，金融操作仍保留人工核对状态。

如果需求变为调整金额或收款人，用户重新发起请求。
人工说明不能修改原授权。已执行交易不提供自动冲正。

## 持久化与审计

`ManualReview` 保存以下内容：

- 所属用户、会话和处理人。
- 关联任务或独立操作。
- 原因、说明和处理结论。
- 创建时间、处理时间和记录状态。

`activeKey` 唯一约束保证一个目标只有一个活动记录。
接管与结论审计分别保存，审计与状态变更共用事务。
审计失败时，该次处理回滚。

并发处理通过条件更新认领记录。后到请求不能覆盖已保存的结论。
工作流和确认执行认领检查活动人工记录。在途执行保留原认领身份。

## 接口与代码入口

| 接口或模块 | 职责 |
| --- | --- |
| `GET /api/manual-reviews` | 查询当前会话的候选与处理记录 |
| `POST /api/manual-reviews` | 提交 `taskId` 或 `actionId` 及原因 |
| `POST /api/manual-reviews/[id]` | 提交 `stop`、`resume` 或 `retry` 及说明 |
| [人工处理业务](../../agent/manual-review.ts) | 归属检查、持久化与事务审计 |
| [接管策略](../../agent/manual-review-policy.ts) | 安全检查点和处理权限 |

接口使用可信 Cookie 会话，核验用户与目标归属。人工处理接口没有注册为模型工具。
当前处理人来自同一演示会话。系统没有独立员工登录或角色分权。

## 验证入口

[接口测试](../../tests/app/manual-review-http.test.ts) 覆盖真实路由、数据库和执行器。
用例检查接管持久化、授权保留、并发决定和审计回滚。
用例也检查在途金融结果只提交一次，以及后继节点停止推进。

浏览器验收中的 `g-manual-handoff` 检查接管、刷新和处理结论。
浏览器使用预置的失败与未知结果，不在此旅程中制造进程崩溃。
执行命令见 [测试说明](test-cases.md)。
