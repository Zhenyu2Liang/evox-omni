# 对话与执行流程审查

本轮修复覆盖对话分类、回复展示、持久化恢复、客户端状态和金融写入边界。
审查依据包括当前数据库中的原始对话、模型请求和工具结果。
测试只使用独立数据库，未清空演示数据库。

## 对话问题

“看看哪个可以取消订阅”属于建议分析。
原设计将这句话当成办理请求。
模型的分析被查询摘要和等待确认提示替换。
用户再次发送“？”后，页面才展示完整分析。

当前设计区分以下用途：

| 用途 | 回复与执行规则 |
| --- | --- |
| 普通交流 | 保留完整自然语言和 Markdown |
| 建议分析 | 可使用已核实的查询快照；不能发起写入或工作流 |
| 查询授权 | 敏感查询仍需确认；确认后继续当前分析问题 |
| 实际办理 | 金融结果由服务端执行回执生成 |

确认旧查询时，服务端核对原模型请求和最新用户问题。
用户已经开始新的话题时，只补充原查询结果。
旧查询不能重新激活先前的建议或办理需求。

消费分析标明查询月份，区分成本与使用习惯假设。
支出增加不能直接证明超过预算。
截图中的金额有工具结果支持，但“本月超支”缺少预算依据。

## 回复格式与重启

保留原模型输出，同时检查不可公开的协议格式。
检查只识别完整协议封套和完整推理标签封套。
普通 JSON、字段词和正文中的代码示例保留。
明确的协议示例由结构化意图标记放行。

每个运行最多生成 1 次完整修正回复。
修正预算、原候选摘要和阶段在发请求前持久化。
进程重启后沿用原预算，不能反复追加修正请求。
模型因输出长度上限停止时，按未完成生成处理。

后续截图中的半句也已出现在数据库原始模型消息中。
该回复仅生成 26 个输出 token，`stopReason` 与 `rawStopReason` 均为 `stop`。
页面保存的正文与原始正文相同。
因此，不能归因于页面截掉后半段。
协议正常结束不代表语言表达已经完成。
这条旧记录没有保存 `[DONE]` 是否到达的证据。
因此，真正根因仍不能确定。

曾增加句尾词语检查，并据此请求重答。
这种启发式不能确定模型或传输是否截断，现已删除。
对应的自动重答、补全失败提示和测试也已删除。
原始回复仍用于供应商协议和传输诊断。
基于金融声明和旧草稿用词的重答判断也已删除。
回复格式检查和持久化纠正预算继续保留。
业务执行事实由独立工具记录、授权和回执说明。

当前修复检查供应商传输协议。
在 Pi 官方 `fetch` 扩展点检查 SSE 的 `[DONE]`。
只有 `stop` 后遇到 EOF，响应按连接失败处理。
即使工具参数已完整，也不能据此创建授权或执行操作。
消息和工具映射仍使用官方 Pi SDK，不重写正文。
收到 `stop` 和 `[DONE]` 的半句仍按原文保留。

Pi 官方回调保存有效请求、白名单响应头和响应增量。
有效请求包含实际传出的 `max_tokens`、`stop` 等字段。
`transport_end` 保存结束状态、字节数和数据帧数。
每条证据绑定实际 `modelRequestId`，模型请求完成前等待写入。
参数碎片只记字节数和脱敏标记，完整调用仍按原 Pi 日志保存。
认证头和凭据不进入这些记录。

正文继续在校验后整段交付。
页面实时显示生成、检查和完善阶段。
传输层保留结束帧中的正文，并处理 UTF-8 跨块和末尾帧。
缺少终态的模型流按失败处理，避免 Pi 的结果等待一直不结束。
回复交付规则见[对话与业务卡片](chat-presentation.md#回复交付方式)。

新用户消息开始新的用途声明。
模型通过 `describe_turn` 提交本轮用途和操作序列。
声明不能替代确认、验证码或金融执行回执。
历史原话和完整工具组继续归档。
模型视图只按已登记摘要的覆盖范围压缩。

## 金融写入边界

首次金融写入在同一事务内重新核对授权。
检查会话状态、所属用户、原参数摘要和验证码状态。
验证码已经过期、已经消费或不匹配原操作时，禁止新写入。
已承诺的红色操作不能通过改变等级降低认证要求。
过期挑战会重新签发，并要求再次提交验证码。
系统不会用本次提交的旧验证码验证新挑战。

已提交操作先核验执行回执。
确认或恢复只回放原结果，不再次执行金融写入。
原验证码后来过期或被消费，不影响已有回执的核验。

SQLite 连接还存在事务隔离缺陷。
原适配器的普通查询与事务共用连接，但未共享互斥锁。
测试复现了脏读和跨请求回滚。
当前连接将普通查询与事务入口统一串行化。
事务内部查询沿用事务句柄，避免重复获取连接锁。

## 客户端状态

聊天传输在进入状态更新前校验事件和卡片结构。
无效响应不能进入卡片渲染。
重置后的旧任务响应和旧授权响应不能恢复到新历史。
同一执行代次的旧计划快照不能覆盖新状态。
同时间戳的合法状态变化仍按到达顺序处理。

断流后，客户端尝试读取 1 次已保存历史。
恢复保留消息 ID、分页位置和完整回复。
客户端不会重发金融请求，也不会将半截输出保存为最终回复。
锁定属于操作终态，不继续展示可提交的验证码输入。
普通页面展示业务错误；开发者模式保留脱敏诊断。
