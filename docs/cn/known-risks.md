# 当前限制

当前项目是银行智能体演示系统。账户、银行交易通道和认证服务均为模拟服务。
持久化恢复不能替代外部银行接口的幂等保证。

## 功能与安全边界

| 范围 | 当前行为 | 尚未提供的能力 |
| --- | --- | --- |
| 金融数值 | 已入账金额使用整数分；比率和估值使用 Decimal | 多币种结算；超出当前数值边界的金额 |
| 身份 | 免登录的固定用户和共享会话 | 生产用户登录、独立员工登录与角色分权 |
| 认证 | 原操作绑定、有效期、失败次数和消费状态 | 短信、人脸或生产认证服务 |
| 银行写入 | 本地事务原子提交变更、审计和执行回执 | 真实银行、支付和商户接口 |
| 模型恢复 | 保存请求与结果，按次数上限重新生成 | 从半截输出的精确令牌位置继续生成 |
| 结果恢复 | 核验执行回执后恢复原结果 | 自动判定外部未知效果 |
| 工作流 | 保存原图、节点调用和提交校验 | 自动解除人工暂停或代替用户授权 |
| 定时任务 | 保存分发状态、提醒和到期付款工作流 | Web 服务内置常驻调度 |
| 生日采购 | 创建预算额度和模拟未来意图 | 真实资金冻结与商户采购 |
| 理财 | 产品对比、追加申购、全额赎回和部分赎回 | 完整的“适当性问卷”与年度报告 |
| 日志 | 凭据脱敏，公开事件与内部事件分开 | 静态加密、保留期限策略与独立员工访问控制 |
| 存储 | 当前 SQLite 模型和写入串行化 | 旧模型转换、多主机故障转移与其他数据库验证 |

金额采用人民币分精度。已入账值限定在有符号 INT64 范围。
Decimal 最多支持 40 位整数和 18 位小数。
数值定义见 [金融数值](financial-values.md)。

## 业务结果的含义

- 理财申购从活期账户扣款，追加申购并入已有持仓。部分赎回按指定本金金额结算，剩余本金继续持有；全额赎回关闭整笔持仓。
- 卡片限额只修改分类消费上限，不调整总授信。虚拟卡绑定活期账户，支持本地模拟消费，未接入真实商户支付。
- 原交易记录没有卡片 ID。异常交易冻结入口要求用户选择卡片。
- 本人交易确认只保存审计记录，不删除异常标记。
- 总资产等于账户余额与持仓估值之和，不扣除信用卡负债。
- 安全中心的开发者重置按钮只解除熔断，不授予原操作执行权。确认和认证仍按原状态处理。
- 有向无环图（DAG）工作流按节点提交，整个计划不是单个事务。后继节点失败不会回退已入账交易。

代码入口见 [理财](../../banking-sdk/investment.ts)、[卡片](../../banking-sdk/card.ts) 和 [资产汇总](../../banking-sdk/dashboard.ts)。
异常处理见 [本人交易确认](../../app/api/transactions/[id]/acknowledge/route.ts) 和 [异常交易卡片](../../components/chat/cards/AnomalyCard.tsx)。

## 语言与脱敏范围

模拟模型使用预置脚本，不能代表在线模型的理解能力。
在线模型根据对话声明本轮用途与步骤，服务端检查结构化计划和授权。
未识别的自然语言不能视为已正确理解的金融指令。

凭据脱敏检查字段名和已定义的文本模式。
脱敏不是通用敏感信息检测，任意自由文本中的凭据仍可能遗漏。
演示环境不得输入真实密码或生产凭据。

规则见 [本轮意图](../../agent/intent-context.ts)、[计划检查](../../agent/tools/plan-compiler.ts) 和 [日志脱敏](../../agent/durable/serialization.ts)。

## 恢复部署边界

恢复处理进程必须独立启动：

```sh
pnpm agent:worker
```

也可以执行 1 轮有界检查：

```sh
pnpm agent:recover
```

Web 服务不会隐式启动恢复循环。
模型请求保留原服务商、端点和输入。
原模型配置或会话版本改变时，系统停止续跑。
未完成模型请求重发前，系统检查原工具声明。
工具声明改变时，系统拒绝重发原请求。
重试次数和退避时间持久化，进程重启不会清空计数。

结果不明的操作停在人工核对状态。
回执损坏或账本缺少执行证据时，系统不重建历史执行格式。
规则见 [持久化与恢复](agent-durability.md)。

## 时钟与数据

权限、认证和执行租约使用真实时间。
业务分析使用明确的 UTC+08:00 演示日期。
调度命令行可以指定可信测试时间，公开请求不能设置时钟。

项目只支持当前数据库模型。`pnpm db:reset` 重建模拟数据。
警告：重置数据库前先保留需要的数据。重置会删除现有模拟记录。

开发与验收流程见 [开发指南](development.md) 和 [测试说明](test-cases.md)。
