# 金融数值与结算

入账金额使用整数分。利率和未舍入估值使用 Decimal。
两类数值按单位区分，不能统一改为 BigInt。

## 类型与单位

| 数值 | 数据库存储 | 程序类型 | 单位 |
| --- | --- | --- | --- |
| 余额、交易、额度、订阅、预算、起购金额 | SQLite INTEGER、Prisma BigInt | bigint | 人民币分 |
| 持仓本金 `principalAmountMinor` | INTEGER | bigint | 人民币分 |
| 年化收益率 `annualYieldRate` | 规范十进制 TEXT | Decimal、字符串 | 无量纲比例 |
| 估值 `estimatedMarketValue` | 可空的十进制 TEXT | Decimal、字符串 | 未舍入的人民币元 |

公开接口的金融数值使用十进制字符串。
例如，200 元写为 `"200.00"`，不能传数字 `200`。
模型、页面和工作流条件均遵守这个约定。
工作流的计数值仍使用独立的 number 类型。

`annualYieldRate` 只有比例含义。
例如，`"0.032575"` 在页面显示为 `3.2575%`。
百分数转换只发生在展示时。

持仓的公开字段 `amount` 表示已入账本金。
`marketValue` 和 `profit` 保留估值精度。
持仓必须包含完整产品信息。
产品信息缺失时，系统报告数据完整性错误。

## Decimal 运算

[Decimal 工具](../../lib/decimal.ts) 使用独立配置。
中间运算精度为 120 位有效数字。
领域数值最多有 40 位整数和 18 位小数。
输入和计算结果均检查这些边界。

- 金融 JSON 数字输入会被拒绝。
- 科学计数法指数在创建 Decimal 前检查。
- 加、减、乘在领域边界内保留精确值。
- 无限小数或超过小数位上限的除法会被拒绝。
- 缺失金额不会自动变成零。

SQLite 的 DECIMAL 声明不能保证十进制精度。
SQLite 可能按二进制浮点数存储该字段。
因此，精确小数保存为规范 TEXT。
仓储层和银行工具检查文本格式与精度。
这些 TEXT 字段不使用 SQLite 的数值运算。

若增加 PostgreSQL 适配器，可使用 NUMERIC。
适配器需明确精度、小数位和领域校验。
图表坐标可转换为 number，金融计算不能转换。

## 赎回结算

入账金额最多保留 2 位小数。
普通金额输入出现小于 1 分的数值时会被拒绝。

模拟赎回按 HALF_UP 舍入到人民币分。
HALF_UP 表示半分及以上向远离零的方向舍入。
估值必须非负，结算只舍入 1 次。
最终金额还需满足有符号 INT64 的存储范围。
这条规则是当前模拟产品的结算约定。

权限网关和银行工具使用同一换算规则。
授权记录绑定舍入后的金额。
提交交易前，银行工具重新读取估值。
结算金额变化时，银行工具拒绝入账。

赎回成功后，原结果同时保存以下字段：

- `redemptionValuation`：原始估值。
- `settlementRounding`：舍入规则。
- 最终结算金额与原执行余额。
- 执行身份和资金账户。

同一执行身份再次请求时，返回原结果。
估值后来变化也不会产生第二次入账。
全部亏损时，零结算金额有效。
负估值和格式错误在写入前失败。

## 申购与原结果重放

申购在同一事务中保存完整的 `subscribeResult`。
重放前，系统核验持仓与原结果。
返回值保留原执行余额和资金账户。
原结果缺失或矛盾时，系统停止并报告冲突。

已提交结果先于当前账户和产品条件读取。
当前账户类型和产品起购金额只约束新操作。
这些条件后来变化，不会改写原成功结果。

赎回重放还核验估值、金额与舍入规则。
传入的授权金额必须匹配原结算金额。
执行回执或账本证据不完整时，转入人工核对。
核验机制见[持久化与恢复](agent-durability.md)。

## 账单与资产汇总

`total` 和 `bookedTotal` 包含全部已入账消费。
`flaggedTotal` 单列可疑消费，不从总额中扣除。
投资现金流不计入消费。
消费分类保留明确的零值，比例使用整数运算。

账户、账单与资产汇总使用同一数据库快照。
资产总额包含现金和未舍入的持仓估值。
因此，资产总额表示估计值，不能当作可提现余额。

## 预算额度

`reserve_budget` 创建预算额度。
预算额度不冻结资金，也不减少可提现余额。

预算使用 `(userId, idempotencyKey)` 唯一键。
同一用户重放时，系统核验原预算参数：

- 名称 `name`。
- 金额 `amount`。
- 用途 `purpose`。
- 到期日期 `dueDate`。

不同用户的相同本地键互不影响。
执行回执、审计和预算变更在同一事务中提交。

## 数据库与产品边界

项目只支持当前 schema 和金融接口。
数据库同步与重置步骤见[开发指南](development.md)。

模拟持仓允许传入明确的估值。
当前系统未接入行情、基金份额或净值定价。
当前系统也未计算利息计提。
增加这些产品时，需要分别定义单位和计算规则。
价格还需记录来源与定价时间。
