# 万象柜坊 EvoX Omni 已实现功能说明

[English](../en/implemented-features.md) | **简体中文**

项目支持通过网页和微信文字对话办理模拟银行业务。
用户描述需求后，银行智能体查询对象、规划步骤并调用银行工具。
需要确认或验证的业务，由服务端暂停执行，等待用户处理。

账户、交易和身份验证均用于演示，未接入真实银行或支付服务。
本说明依据当前代码整理，不代表本次重新执行了全部验收。

## 1. 使用入口

| 入口 | 功能 |
| --- | --- |
| 网页 AI 助手 `/agent` | 自然语言对话、业务结果卡片、操作确认、验证码和多步任务控制 |
| 微信通道 | 文字私聊、业务结果、显式确认与验证、任务控制和到期检查 |
| 业务页面 | 查看资产、账单、卡片、理财、订阅、联系人和定时任务 |
| 操作记录与安全中心 | 查看业务处理状态、验证记录和安全锁定状态 |
| 开发者模式 | 查看运行、审计和执行证据，使用人工核对与演示维护入口 |

网页使用固定演示用户，无需登录。
不同浏览器与绑定的微信用户共享同一演示账户和对话。
界面默认中文，支持切换英文。

## 2. 自然语言对话

银行智能体支持交流、业务咨询、数据查询和业务办理。
咨询某项业务的办理方法，不等于授权执行该业务。
缺少金额、收款人或目标卡片时，模型可继续询问。

对话能力包括：

- 保留多轮对话上下文。
- 查询联系人、账户、卡片和产品后，使用准确对象发起业务。
- 保存完整对话归档，分页查看历史消息。
- 搜索历史原话，保留原金额、负号和更正内容。
- 使用 Pi 官方接口压缩模型上下文，原始归档继续保留。
- 展示查询结果、操作详情、执行回执和任务节点状态。

模型正文用于解释，业务卡片用于展示服务端事实。
普通聊天中的“确认”不能代替操作确认或验证码。
在线模型仍可能理解错误或未发起业务，用户需核对实际操作卡片。

## 3. 账户与转账

### 3.1 账户查询

- 查询活期账户和储蓄账户余额。
- 查询资产总览、当月已入账消费和信用卡可用授信。
- 按姓名、手机号或备注查找已有联系人。
- 在联系人页添加或删除联系人。

资产总览汇总账户余额与理财持仓估值。
信用卡可用授信单独展示，不作为存款余额重复计入资产。

### 3.2 智能转账

- 按已有联系人姓名、手机号或备注解析收款人。
- 指定转账金额、备注和受支持的付款账户。
- 执行前展示收款人、金额、付款账户和风险等级。
- 确认后扣款，并写入交易流水和执行回执。
- 取消尚未执行的操作。

转账使用所属用户的活期账户。
单笔金额或当日累计金额超过 1000.00 元时，需要强验证。
确认时重新核对累计风险，已授权的在途转账也参与累计。
重复确认或消息重复投递不能重复扣款。

示例：`从活期账户转账200.37元给张伟，备注打车。`

具体权限规则见[安全设计](security.md#权限等级)。

## 4. 账单分析与异常交易

- 按时间、分类和条数查询交易流水。
- 按月统计消费分类、消费总额和环比变化。
- 在 `/bills/reports` 查看月度、年度账单报告，按需生成模型分析。
- 导出 CSV、含图表和分析的 HTML 或 PDF。
- 查看消费趋势、商户统计和单笔消费信息。
- 根据已配置规则识别可疑交易，并展示原因。
- 在网页将可疑交易标记为本人交易。

可疑消费仍保留在已入账消费总额中，并单独展示。
异常标记不等于确认欺诈，也不会自动冻结卡片。
本人交易确认保存处理记录，不删除原流水或异常标记。

示例：`分析2026年9月的消费分类，并检查异常交易。`

报告使用方法、统计口径与导出格式见[账单报告](bill-reports.md)。

## 5. 理财产品与持仓

### 5.1 产品查询与比较

- 查看产品风险等级、预期年化收益率、期限和起购金额。
- 比较理财产品。
- 查看剩余持仓成本、按份额与最新净值推导的市值和持仓收益。
- 根据查询结果回答产品差异与选择问题。

### 5.2 申购与追加申购

申购从活期账户扣款，并保存持仓、资金流水和回执。
再次申购同一已持有产品时，金额并入已有持仓。
页面展示最近申购时间和购买次数。

示例：`从活期账户申购1000元稳健理财A。`

### 5.3 全额、按份额与按金额赎回

赎回必须声明以下 3 种口径之一：

- `SHARES`：按份额赎回。
- `AMOUNT`：按金额赎回。
- `ALL`：赎回全部份额并关闭持仓。

缺少口径、口径未知或混用口径，均为澄清，不套用默认值。
已退役的 `redeemAmount` 同属澄清。
按金额赎回时，服务端按最新净值折算份额，并向下取整到 6 位小数。
结算金额只做 1 次 `HALF_UP` 舍入到分。
全额赎回结清整笔持仓。
按份额或按金额赎回保持持仓，剩余成本按比例摊减，已实现收益可为负。

赎回金额转入活期账户，同时保存资金流水和回执。
重复提交同一执行身份时，返回原结果，不重复入账。

示例：`从稳健理财A持仓中按金额赎回 1000 元，保留剩余持仓。`
示例：`从稳健理财A持仓中赎回 500 份。`

申购和赎回均需确认与强验证。
预期收益和市值属于演示估值。
系统未提供完整的风险承受能力评估问卷。
口径与结算规则见[理财产品](investments.md)，金额规则见[金融数值与结算](financial-values.md)。

## 6. 卡片管理与虚拟卡

### 6.1 卡片查询与控制

- 查询借记卡、信用卡和虚拟卡的状态与限额。
- 设置分类消费限额，不修改银行授信额度。
- 临时冻结卡片，并在需要时解冻。
- 正式挂失卡片，并为已挂失卡片补办新卡。
- 在卡片页添加或删除模拟卡片记录。

临时冻结可以解除。
正式挂失不可撤销，找到原卡后也不能恢复原卡。
补办生成同类型的新卡号，原卡保持已挂失状态。
信用卡补办继承原授信与当前可用额度；原卡为已挂失终态，不计入可用授信汇总。

新建实体借记卡、信用卡和删除卡片记录由网页办理。
银行智能体可办理虚拟卡申请及已挂失卡片补办。
页面添加卡片不代表真实开户或授信审批。

### 6.2 绑定活期账户的虚拟卡

借记卡与虚拟卡都绑定本人结算账户，卡片本身不持有余额。
虚拟卡消费扣减结算账户的资金；多张虚拟卡绑定同一账户时，共享该账户资金。
绑定账户缺失或校验不通过时，卡片省略余额字段，不显示为 0。

- 申请时校验账户归属和活期账户类型。
- 展示账户可用余额、月消费限额和当前可支付金额。
- 模拟消费时扣减绑定账户，并保存流水和卡片消费记录。
- 冻结或挂失状态不能消费。
- 补办后保留结算账户，延续当月剩余消费限额。

当前可支付金额取账户可用余额与月剩余限额的较小值。
未设置月限额时，以账户可用余额为资金上限。
月限额设为 0 时不能消费。

示例：`申请一张月消费限额100元、绑定活期账户的虚拟卡。`

虚拟卡消费为本地模拟，未接入真实商户支付。
卡片页面流程与删除限制见[卡片管理](card-management.md)。

## 7. 订阅与代扣管理

- 查询演示数据中的订阅和代扣记录。
- 查看扣费金额、周期、下次扣费时间和订阅状态。
- 开启或关闭续费提醒。
- 取消订阅。
- 结合费用和用户需求回答订阅取舍问题。

查询订阅需要确认。
取消订阅或更改提醒也需要确认。
询问“哪个订阅可以取消”只产生分析，不直接取消服务。
这些操作修改本地模拟记录，未接入真实订阅商户。

示例：`取消Netflix订阅，并开启Spotify的续费提醒。`

## 8. 预算与定时任务

### 8.1 预算记录

系统可登记预算名称、金额和用途。
预算只用于记账，不冻结或转移账户资金。

示例：`登记500.50元生日礼物预算，只记账不转账。`

### 8.2 定时提醒与付款意图

- 按指定日期和时间保存提醒、转账或付款意图。
- 展示定时任务状态和提醒通知。
- 通过页面、微信命令或命令行检查到期任务。
- 提醒到期后保存通知。
- 付款到期后创建原付款工作流，再检查确认和验证要求。
- 重复检查复用原任务，避免重复通知或重复创建付款入口。

Web 服务启动不会自动运行常驻调度。
需要后台定期检查时，另行配置调度服务调用检查命令。
微信当前通过主动查询或检查到期返回通知，没有自动到点推送。

示例：`在2099年12月20日上午9点提醒我检查账单，只提醒，不付款。`

日期与分发规则见[定时任务与提醒](scheduled-tasks.md)。

## 9. 跨场景工作流

复杂请求可编排为有向无环图（DAG）工作流。
每个节点保留依赖关系、执行状态和原操作身份。

- 按步骤执行查询、限额调整、预算和定时任务等业务。
- 使用用户明确要求的条件控制后续步骤。
- 暂停、继续、取消和重试受支持的任务。
- 刷新后恢复任务状态及待确认入口。
- 回退可撤销的预算或定时记录。
- 在开发者模式提交人工接管并登记核对结论。

提交计划不等于授权计划内的银行写操作。
各节点仍独立经过权限检查，确认和验证不能跨操作复用。
取消阻止后续执行，已入账交易保留。
工作流不提供整个计划的资金回滚。

示例：`先分析2026年9月消费，再把借记卡购物分类限额设为900.50元，最后登记219.87元预算。每一步成功后再做下一步。`

生日场景可组合预算、提醒与未来付款意图。
系统不会实际冻结生日预算，也不会向商户订购鲜花或蛋糕。
人工处理边界见[人工核对](manual-review.md)。

## 10. 微信通道

微信通道使用 `pi-weixinbot` 协议模块连接现有银行服务。
扫码登录后，仅接收绑定用户的完整文字私聊。
自然语言业务沿用网页的工具、权限、审计和执行回执。

| 交互 | 微信命令 |
| --- | --- |
| 查看帮助与待处理操作 | `/帮助`、`/待办` |
| 确认、验证、取消指定操作 | `/确认 操作编号`、`/验证 操作编号 六位验证码`、`/取消 操作编号` |
| 查看或控制任务 | `/任务`、`/暂停 任务编号`、`/继续 任务编号`、`/取消任务 任务编号` |
| 重试或回退记录 | `/重试 任务编号`、`/回退记录 任务编号` |
| 核对并恢复原操作 | `/恢复操作 操作编号` |
| 查看定时任务及检查到期 | `/定时任务`、`/检查到期` |

确认前先展示服务端操作详情，验证码命令不交给模型。
群聊、陌生人和机器人回声不进入银行智能体。
当前不识别微信图片、文件或语音，也不提供多人银行身份绑定。
配置和操作说明见[微信通道](weixin.md)。

## 11. 安全、记录与恢复

服务端提供以下机制：

- 按绿色、黄色和红色权限控制自动执行、确认及强验证。
- 检查资源归属、参数类型和金额范围。
- 限制模型使用已注册的银行工具，不提供任意代码执行能力。
- 将验证码挑战绑定原操作，限制有效期和失败次数。
- 验证码失败达到上限时，该操作由 `pending` 或 `awaiting_mfa` 比较并交换写成 `locked`。
- `locked` 此后不再提示、验证、取消或恢复。
- 熔断锁按账户所有者（`user:<userId>`）判定，同一账户的其他操作也报告锁定。
- 顶层失败码始终是 `CIRCUIT_OPEN`，原因由 `failure` 区分。
- 本操作耗尽尝试：`failure.code` 为 `MFA_LOCKED`，`reason` 为 `mfa_attempts_exhausted`。
- 账户在别处熔断：`failure.code` 为 `CIRCUIT_OPEN`，`reason` 为 `circuit_open`。
- 内部标记不进入用户可见文本。
- 将熔断状态保存到数据库，记录失败、锁定和解除事件。
- 将业务写入、必需审计和执行回执放入同一事务。
- 使用执行身份去重，重复请求读取原结果。
- 保存模型请求、事件日志、工具调用和恢复检查点。
- 遇到结果不明的操作时转入人工核对，保留执行证据。

普通用户可在“操作记录”查看业务处理状态。
开发者可在“操作审计”和“运行记录”查看执行证据。
恢复服务需单独启动，不随 Web 服务自动常驻。

当前验证使用演示验证码 `123456`，系统不发送短信。
项目未提供生产登录、真实人脸认证或独立员工角色管理。
设计说明见[安全设计](security.md)及[持久化与恢复](agent-durability.md)。

## 12. 竞赛场景覆盖与边界

| 赛题场景 | 已提供的功能 | 当前边界 |
| --- | --- | --- |
| 智能转账 | 联系人解析、确认、累计风控、强验证、到期付款工作流 | 无真实资金转账；未提供 AA 收款产品流程 |
| 账单分析 | 流水、月度与年度报告、分类统计、模型解读、PDF/HTML/CSV 导出、异常识别、本人交易标记 | 仅模拟人民币已入账流水；PDF 需本地浏览器 |
| 理财操作 | 产品比较、持仓、申购合并、全额、按份额与按金额赎回 | 无完整风险承受能力评估问卷或真实销售系统 |
| 卡片管理 | 查询、分类限额、冻结与解冻、挂失与补办、虚拟卡 | 不审批授信额度；页面增删仅管理模拟记录 |
| 订阅代扣管理 | 查询、续费提醒设置、取消订阅 | 未对接外部商户取消接口或自动到点推送 |
| 跨场景联动 | 工作流、预算、提醒和未来付款意图 | 不冻结预算，不实际采购商品 |
| 多渠道接入 | 网页与微信文字对话 | 单一演示账户，不支持群聊、语音或多人认证 |

在线模型模式调用真实模型服务，银行业务仍在本地模拟环境执行。
模拟模型模式使用脚本响应，适用于离线演示和确定性测试。
多进程、多实例和真实银行环境的可靠性不能由本地演示证明。
