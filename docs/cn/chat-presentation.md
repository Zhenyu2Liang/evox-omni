# 对话与业务卡片

## 回复交付方式

正文在模型请求结束并通过已有检查后整段展示。
完整传输和回复格式通过检查后，才交给页面。
工具、计划和回复阶段通过 SSE 实时更新。
页面分别显示“正在生成回复”“正在检查回复”和“正在完善回复”。
当前方式没有逐字展示模型正文。
赛题要求安全办理和自然对话，未要求逐字流式文字。
业务卡片只展示真实工具结果、授权和回执。

模型的 `stop` 表示供应商标记了生成结束。
当前 OpenAI 兼容流还必须收到 SSE 的 `[DONE]`。
只有 `stop` 后断开连接，仍按连接失败处理。
仅提出完整工具参数，也不能跳过流结束检查。
未完成的响应不能据此创建授权或执行操作。

`stop` 和 `[DONE]` 都不能证明句子已经写完。
两者均收到时，正文仍按供应商原文保留。
回复交付以供应商协议、完整传输和持久化记录为依据。
页面不根据句尾词语猜测截断，也不自动补写后半句。
回复格式问题沿用原上下文纠正，至多 1 次。
正文中的金额、旧草稿词和字段名不触发重答。
原始候选、纠正请求和结果仍保存在运行记录中。
持久化规则见 [回复纠正与建议续答](agent-durability.md#回复纠正与建议续答)。

供应商请求和响应另有服务端审计记录。
记录关联实际模型请求，包含请求正文与流结束证据。
旧截图没有保存 `[DONE]` 证据，尚不能确定真正根因。

聊天表单在客户端事件处理就绪前保持禁用。
页面恢复查询最多等待 5 秒，覆盖请求和 JSON 解码。
取消、卸载或读取失败会结束恢复状态。
迟到的结果不能覆盖新对话，已有消息和操作卡片继续保留。

## 正常交流

模型通过 `describe_turn` 声明本轮用途。
用途包含交流、建议、查询和办理。
声明只约束工具提议，不授予银行操作权限。
声明调用保存在运行记录中，不显示为聊天工具卡。
在线流程不按用户句子中的词语推断用途。

办理准备阶段可先查询对象和数量。
确认查询后，可继续规划原请求中的办理步骤。
包含写入的操作序列一旦绑定，就不能改变。
查询确认不能代替后续写入的确认或验证码。

交流用途保留正常问答。
普通交流保留自然文字，可使用 Markdown 排版。
例如，询问资金来源时，说明默认活期账户和指定账户的方式。
询问定时任务能力时，说明支持的任务和所需参数。
这些问题不要求模型创建任务计划或操作卡片。

普通交流可以通过绿色查询解释账户情况。
服务端阻止交流过程中的写操作和计划提交。
需要授权的查询也不能因能力咨询而生成操作卡片。
新用户消息使用新的轮次声明。
模型继续保留用户原话、工具结果和正常解释。
缺失的用户消息从已保存的对话中补回。
补回只使用用户原话，不生成工具结果或授权记录。
历史中的请求和金额不代表当前授权。
用户页面的历史消息和运行记录仍保留。
后续明确的业务请求仍进入原有授权流程。
已经创建的待确认操作保留授权记录和请求面板。

是否能办理由本轮声明、授权和执行入口校验。
一般规则、假设示例和历史原话引用保持完整。

模型可以根据历史的结构化工具结果解释和分析。
历史查询结果描述查询时的数据。
历史工具结果不代表本轮新增执行。
历史助手文字不提供余额或执行证据。

业务建议保留完整分析，不只显示查询摘要。
例如，“哪个订阅可以取消”是在询问建议。
模型可以比较费用、询问使用频率并说明取舍。
建议本身不能取消订阅或提交工作流。
已有查询结果可作为注明时间的分析依据。
需要新查询时，该查询仍遵守红黄绿权限规则。
查询确认后，用户仍在询问同一问题时，模型继续分析。
用户已经发送其他问题时，只展示原查询结果。
系统不会自动恢复旧建议问题。

模型输出还需通过回复格式检查。
检查只识别完整协议封套和完整推理标签封套。
JSON 封套须能完整解析，并符合协议结构。
普通业务 JSON、历史引语和正文中的代码示例保留。
明确的协议示例通过结构化意图标记放行。
发现格式问题时，模型在原上下文中完整重答一次。
再次失败时，页面说明无法生成可展示的回复。
原始候选和纠正结果继续保存在内部归档中。

同一运行的纠正次数和阶段先保存到检查点。
进程重启后，已完成的纠正不会再次请求模型。
输出达到 token 上限时，视为未完成回复。
页面显示生成失败提示，不使用空白交流模板代替。

模型正文保留原有解释、分析和 Markdown 排版。
正文不作为余额、授权或完成执行的证据。
本轮执行状态由业务卡片中的真实结果说明。
格式纠正过程不能创建授权或执行写操作。

新一轮消息重新生成系统规则。
崩溃恢复已有模型请求时，保留原请求的系统消息。
恢复不能把新规则混入已经记录的请求。

## 无效金额

工具和计划的金额参数使用精确十进制字符串。
服务端检查参数类型、精度和对应业务的金额范围。
参数无效时，停止创建授权或提交金融命令。
转账、申购和预算金额必须大于 0。
消费限额允许设为 0，负数限额仍无效。
关于负数的解释、假设和历史回顾继续正常交流。
模拟模型可以按离线脚本说明无效金额。
在线流程保留完整用户原话，不在输入前解析金额。

## 历史消息

正常使用持续保存完整对话和原始模型消息。
显示分页和模型上下文压缩不删除归档记录。
聊天页首次显示最近 20 条消息。
用户可点击“加载更早的消息”，每次读取前 20 条。
消息按原顺序显示，加载后保留当前阅读位置。
每次工具调用占 1 条独立记录。
记录包含业务名称、状态和该调用的结果卡片。
助手正文另占 1 条消息，单条正文保持完整。

历史页使用消息标识定位，时间相同也不会遗漏消息。
读取历史时，服务端补充当前授权和工作流状态。
较早的待确认卡片可显示后续已执行或取消的状态。
新消息追加后，原分页标识继续有效。

开发者清空对话时，服务端更换历史版本标识。
旧版本的分页请求不能加入新对话。
页面提示历史已改变时，重新读取当前对话。
普通刷新只读取记录，不删除归档。

回复连接中断后，页面读取最近 20 条保存的消息。
这次读取最多等待 5 秒，不重新提交金融请求。
已保存的完整答复更新原消息，不重复显示用户输入。
原有历史分页和已加载的消息继续保留。
未完成的流式文字不会被当作最终答复保存。
页面保留连接中断提示，供用户核对操作记录。
清空对话后，旧请求和旧恢复结果不能加入新对话。

需要逐字回顾历史时，模型可查询原始对话归档。
归档查询只返回用户和助手的文字。
工具结果和授权仍使用各自的执行记录。

## 业务事实

普通模式展示业务结果，开发者模式展示调用详情。
卡片只使用工具结果、执行凭证和授权记录。
模型文字和调用参数不能作为操作成功的证据。

| `search_contact` | 匹配的联系人、脱敏手机号和银行。 |

| `detect_anomaly` | 异常消费和可执行的处理入口。 |
| `get_dashboard_summary` | 资产概览和查询时间。 |
| `get_cards` | 卡片状态、脱敏卡号和额度。 |

| `report_lost_card` | 挂失后的卡片信息。 |
| `list_subscriptions` | 订阅价格、周期、扣费日期和提醒。 |

| `list_investments`、`compare_investments` | 产品、风险、收益率、期限和起购金额。 |
| `get_investment_holdings` | 持仓状态、本金及已提供的估值。 |

| `transfer_money` | 收款人、转账金额和操作后余额。 |
| `submit_plan` | 工作流步骤、状态和控制入口。 |

需要确认或验证时，在输入区上方展示请求面板。
实际执行完成后，再展示对应结果卡片。
确认后继续和检查点恢复使用相同映射。
刷新时按原授权记录恢复结果，避免重复卡片。
金融写操作的授权结果由服务端直接生成。
模拟模型和在线模型都不为写操作结果播报重跑模型。
仍在处理的查询或建议问题可在确认后继续生成分析。
该续答只使用已确认的查询结果，不能提交写操作。
延迟确认只更新原工具结果，保留中间收到的对话。

金融查询和执行结果由服务端根据实际记录展示。
业务卡片按授权状态和执行凭证说明实际结果。
助手正文独立展示自然解释和建议。
添加和删除演示卡片使用[卡片管理](card-management.md)页面。

## 任务计划

每个计划只在所属工具记录中展示一次。
授权、执行和恢复产生的新状态更新同一张卡片。
已完成和已取消的计划保留为历史记录。
用户发送新消息后，旧计划不会移到对话底部。

刷新页面时，从数据库读取计划和节点的实际状态。
原始运行和工具调用标识用于确定所属消息。
后续授权运行再次发布旧消息时，不改变其所属运行。
所属记录缺失时，按计划创建时间插入独立计划记录。
开发者清空记录后，只恢复新记录范围内的计划。

暂停、继续、取消和重试按钮始终提交该卡片的计划标识。
旧卡片的按钮不会控制后面创建的计划。
较旧执行代次的更新不能覆盖新状态。
同一执行代次中，较旧时间的快照不能覆盖新状态。
较新执行代次优先，不受服务器时钟回调影响。
同一时间戳下的状态变化按收到的顺序处理。
已完成计划不会被延迟的进度消息改回执行中。
预算或定时任务支持的取消和补偿仍使用明确的计划控制请求。

## 普通模式

桌面消息区最大宽度为 1152 px。
助手正文靠左显示，最大宽度为 832 px。
用户消息靠右显示，最大宽度为 640 px。
两侧显示身份标记，正文宽度随内容和屏幕调整。
业务操作独立展示，左侧边缘与助手正文相同。
手机页面保留左右区分，表格在卡片内横向滚动。

业务卡片使用紧凑标题、指标区和响应式网格。
工具进度使用业务名称和实际状态。
每次调用和结果按顺序显示为独立记录。
查询结果可以先显示，助手分析随后另起一条消息。
后续状态更新原记录，聊天底部不再重复显示工具。
确认和验证码输入只在输入区上方的请求面板展示。
面板不随消息列表滚动，处理完成后收起。
短视口中只滚动操作详情，标题和按钮保持可见。
验证码错误时，面板保留并说明错误。
切换到下一项操作时，验证码输入清空。
刷新页面后恢复待处理请求，不恢复验证码草稿。
所属调用保留只读授权记录，不提供确认按钮。
记录显示发起时的确认要求和当前处理状态。
已授权但尚未执行时，显示“已授权，处理中”。
完成、取消、失败和验证锁定分别展示。
结果未知时，显示待核对，不能显示完成。
较早的所属记录未加载时，请求面板仍可使用。
已有结果卡片时，不重复展开成功摘要。
未知工具使用通用业务名称，不显示原始工具名。
确认请求保留收款人、金额和风险等级。
锁定是授权操作的终态，页面不再显示验证输入。
延迟的确认或验证事件不能重新打开已结束操作。
回复事件、消息内容和卡片数据先校验，再展示。
无法读取的格式显示错误提示，不直接传入卡片组件。

金额使用原有整数分格式化函数。
估值和收益率使用 Decimal 格式化函数。
已赎回持仓不计入当前持仓合计。
估值缺失时，不用本金或零补齐未知值。
已取消订阅不展示未来扣费提示。
创建预算不代表扣款或冻结资金。
创建定时任务不代表支付已完成。
系统没有密码凭证，也不提供密码修改工具。

## 开发者模式

启用后，每次调用可展开“查看调用详情”。
详情显示原始工具名、调用标识和操作标识。
参数来自该调用的真实记录，不由前端推测。
没有参数记录时，界面明确说明未记录。
停用后，详情从对话界面移除。

服务端先对参数脱敏，展示前再次检查。
密码、验证码、密钥、令牌和凭证文字均被隐藏。
手机号只保留末尾 4 位。
推理内容不进入调用详情。
嵌套数据的深度和大小有限制，避免撑满界面。
原始调用事件仍保存在运行记录中。
模型纠正指令和未知错误诊断只显示在开发者详情中。
普通模式使用业务错误说明，保留余额不足等具体原因。
页面错误提示和任务失败说明也使用相同规则。
公开错误码保留资源不存在、验证失败等业务类别。
验证码剩余次数、过期和已使用状态保留具体说明。
未知的运行错误只在脱敏后的开发者详情中展示。
