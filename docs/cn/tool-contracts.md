# 银行工具契约

银行工具只接受明确参数，返回结构化事实或错误。
模型理解对话，安全网关决定是否可以办理。
工具结果不能用自然语言成功声明代替。

## 执行入口

工具名称和权限定义来自 [工具目录](../../lib/contracts/tool-catalog.ts)。
[注册表](../../agent/tools/index.ts)绑定服务器提供的用户身份。
模型不能提供用户身份、执行租约或幂等键。
卡片创建和删除使用卡片管理页面。
系统没有密码凭证，已删除模拟密码修改工具。

每次模型调用依次经过以下检查：

1. 同一模型回复中的调用 ID 非空且不重复。
2. 原始参数符合公开 schema，无隐式类型转换。
3. 本轮声明允许提出该能力。
4. 网关检查所属用户、风险等级和授权状态。
5. 写入事务检查执行权，保存业务结果和回执。

不同模型回复可以复用调用 ID。
运行 ID、模型请求 ID 和调用 ID 共同标识调用。
工作流节点使用服务器生成的执行身份。

## 参数与错误

缺少必填参数、未知字段和错误类型均报 `VALIDATION`。
金额采用精确十进制字符串。
转账、申购和预算金额必须大于 0。
消费限额允许为 0，精度最多到分。
原始参数在 Pi 类型转换前校验。
计划提交前校验所有节点，不先执行再补参数。

不存在或不属于当前用户的资源均报 `NOT_FOUND`。
选中资源必须使用真实业务 ID。
搜索词用于返回候选，不能证明执行身份。
模糊联系人匹配报 `CONFLICT`，返回安全候选。

| 错误代码 | 模型后续处理 |
| --- | --- |
| `VALIDATION` | 修正参数或询问缺失信息。 |
| `NOT_FOUND` | 查询可用对象，请用户重新选择。 |
| `INSUFFICIENT_FUNDS` | 说明资金不足，不能自行更换账户或降低金额。 |
| `LIMIT_EXCEEDED` | 说明限额，不能拆单规避限制。 |
| `SECURITY_DENIED` | 说明能力或权限限制，不能绕过网关。 |
| `MFA_FAILED` | 使用现有验证界面，不能在聊天中索取凭证。 |
| `CIRCUIT_OPEN` | 通过安全界面处理锁定。 |
| `CONFLICT` | 先核对当前对象或已保存的办理状态。 |
| `TOOL_FAILED`、`INTERNAL` | 先核对执行记录，不能直接重提写入或宣称成功。 |

错误代码来自业务契约，不从错误文字中提取。
内部 SQL、文件路径和原始基础设施异常不交给模型。
模型的下一步提示不授予重试权限。
自动恢复仍需核对回执、执行权和重试预算。

## 查询工具

查询得到空集合是成功，不等于工具失败。
错误筛选条件不能被忽略后扩大查询范围。

| 工具 | 输入边界与结果含义 |
| --- | --- |
| `get_balance` | 返回所属用户的存款账户及查询余额；账号脱敏。 |
| `get_transactions` | 时间戳为整数，范围采用 `[from, to)`；要求 `from < to`。默认最近 50 条，最多 200 条。收入与支出合计只覆盖返回记录。 |
| `search_contact` | 查询文字必须为合法文本；返回候选联系人及业务 ID。 |
| `search_conversation_history` | 查询当前会话的原始文字；页码和条数不做字符串转换。历史文字不代表当前授权。 |
| `analyze_spending` | 月份采用合法 `YYYY-MM`；返回完整月份的消费统计。 |
| `detect_anomaly` | 返回筛查标记及对应交易，不能证明盗刷或退款资格。 |
| `get_cards` | 返回所属用户的卡片、状态和分类限额。 |
| `list_subscriptions` | 黄色查询，确认后返回生效订阅；查询确认不能代替取消确认。 |
| `list_investments` | 风险等级只接受 `R1` 至 `R5`；未匹配产品返回空集合。 |
| `compare_investments` | 产品集合不能为空；任一 ID 不存在则报错，不只比较剩余项。重复 ID 去重。 |
| `get_investment_holdings` | 返回所属用户的持仓及估值；本金和未舍入估值分别提供。持仓另含最近申购时间和购买记录。 |
| `get_dashboard_summary` | 返回资产、消费和交易快照；信用卡可用额度不计入存款资产。 |
| `list_scheduled_tasks` | 返回所属用户的任务状态和计划参数；内部派发诊断不进入模型数据。 |

月份使用银行业务时区。
金融日历保留实际年份，不将 0 至 99 年映射为 1900 至 1999 年。
跨页或受条数限制的查询不能冒充完整月度统计。

## 写入工具

| 工具 | 授权与执行边界 |
| --- | --- |
| `transfer_money` | 按金额和日累计决定黄色或红色；收款人及付款账户必须属于明确候选。余额不足、额度不足、错误账户和无效金额报错。 |
| `set_card_limit` | 黄色；分类来自正式目录，只处理正常或已冻结卡片。挂失卡报冲突。 |
| `freeze_card`、`unfreeze_card` | 红色；事务内重读状态。相同状态可幂等返回，冲突状态不能被旧快照覆盖。 |
| `report_lost_card` | 红色；校验所属用户、当前状态和挂失原因。 |
| `cancel_subscription` | 黄色；取消后关闭提醒，相同已取消状态可幂等返回。 |
| `set_subscription_reminder` | 黄色；必须是布尔值，已取消的订阅不能修改提醒。 |
| `reserve_budget` | 绿色；只创建记账预算，不冻结、扣减或转移账户资金。 |
| `create_scheduled_task` | 黄色；创建前校验任务类型、时间和载荷。提醒载荷只含文本，付款载荷必须有唯一收款选择及正数金额。 |
| `subscribe_investment` | 红色；检查产品、起投金额、付款账户及余额。已持有该产品时，金额并入原持仓，本金和市值各增加本次金额。 |
| `redeem_investment` | 红色；绑定真实持仓和服务器报价，支持全额或部分赎回。`redeemAmount` 为可选的赎回本金。缺省或等于持仓本金时全额赎回。小于持仓本金的正数金额按该本金比例结算，超过持仓本金报错。报价变化需要重新确认。 |

投资申赎的公开结果包含操作后余额。
赎回结果另含 `redemptionValuation` 和 `settlementRounding`。
部分赎回返回 `partial`、`redeemedPrincipal` 和 `remainingPrincipal`。
追加申购返回 `addedToExisting` 和本次申购时间 `lastPurchaseAt`。

写入的幂等键只来自服务器执行选项。
同一键必须匹配同一用户、工具和参数摘要。
已有回执先返回原结果，不能再次修改资金。
状态相同不代表不同命令可以共用回执。

定时提醒的到期投递无需银行办理确认。
定时付款和转账在到期时仍需确认或强验证。
`requiresConfirmation` 由服务器生成，模型不能设置。
创建定时任务不能提前批准未来的付款。

`submit_plan` 先校验任务图，再登记全部节点。
依赖、条件、输出引用和声明的写入序列必须一致。
每个敏感节点分别授权，前一个节点的确认不能授权后一个节点。
计划失败仍保留已经成功的节点结果。
计划不是跨业务的全局原子事务。

## 模型与界面的保存信息

Pi 将 `content` 发给模型。
`details` 和 `structuredContent` 供界面及程序使用。
只把数据放入 `details` 会使模型看不到完整业务事实。

[结果适配器](../../agent/tools/result.ts)统一生成工具结果：

- 成功内容包含摘要及完整的公开业务 JSON。
- 失败使用 Pi 原生 `isError: true`。
- 失败内容包含 `bankingError`、错误代码和下一步提示。
- 失败计划保留节点结果，不能显示为整项成功。
- 业务 ID、金融数值和归档原文保持完整。
- 用户内部身份、执行键、租约及派发诊断不发给模型。
- 手机号和凭证在模型数据中脱敏。

界面使用独立的卡片投影，只展示真实业务结果。
开发者模式可以查看调用参数和执行记录。
确认后的查询也使用同一个模型结果适配器。
模型能承接原问题，并读取完成查询中的对象 ID。

日志保存完整工具内容、结构化结果及可用的耗时和用量。
恢复不能只重建第一段摘要。
未完成参数片段可以含凭证，因此片段只保留脱敏事件。
完成后的调用参数仍按字段保存和脱敏。
恢复规则见[持久化与恢复](agent-durability.md)。
