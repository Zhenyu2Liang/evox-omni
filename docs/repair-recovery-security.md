## 已修复

1. **恢复不能绕过熔断产生首次扣款。** 必需执行审计失败时，原转账全部回滚、动作保留 `confirmed`。后续无凭证恢复经 `security/recovery-authorization.ts` 重新核对服务端身份、会话、熔断、计划取消、累计金额及 MFA；SDK 写事务内再次检查熔断。锁定返回 HTTP 423 且余额、流水、回执均不变。已提交凭证的只读回填仍可进行，不新增副作用。累计风险升级时返回 RED / `awaiting_mfa`，验证后才可扣款。两次恢复同时读到凭证缺失时，后完成的授权检查识别竞争者已提交的账本，不重复累计或误降级已执行动作。
2. **卡片与订阅写操作核对资源所有者。** 工具显式传入服务端 `userId`，忽略模型参数中伪造的身份；SDK 要求该身份并拒绝外人资源。实际写入条件包含所有者，卡片限额的删除与条件关联创建在同一事务，防止读取后所有者变化导致越权。覆盖限额、冻结、解冻、挂失、取消订阅、订阅提醒。有效本人会话操作外人资源时，当前工具协议返回 HTTP 200 / `data.ok=false`，不是 HTTP 403；没有业务写入。
3. **人工核对可以和原成功审计同时保留。** 执行使用 `exec:<actionId>`，人工核对使用 `reconcile:<actionId>`。凭证与账本矛盾时，动作 `needs_reconciliation` 与严格核对审计同事务落地，原成功审计不被覆盖。接口返回 `ok=false` 与人工核对提示；重复恢复不新增扣款或核对事件。核对审计故障时状态事务回滚，后续可以重试。

恢复执行提示同步纠正：首次尝试已回滚时，不再声称“此前已执行”；只在已核验提交事实的只读恢复分支说明此前执行成功。
