# 多步 live 办理完整计划验收

分支 `genesis/agent_841944ee`，基线 `a4abc10`。无 schema 变更，不需要重置开发库。

## 修复

原路径允许模型针对两笔转账需求只生成第一笔独立确认卡。live 确认后不再调用模型，剩余步骤没有持久化，因而丢失。现在显式多步需求必须先提交完整 DAG；在创建计划、自动预算或确认入口前按实际工具、对象和分金额逐步校验，拒绝遗漏、额外写节点和金额/对象错配。独立网关调用同样受约束；计划上下文由服务器执行器提供，不读取模型参数里的计划标识。

进入网关/执行器前的预检拒绝由运行时按工具调用身份记录，只有这种可信的未执行拒绝可使用既有的一次规划恢复。恢复仍不完整则不创建授权，保存明确提示与重试入口。实际计划、写操作或授权一旦开始，不自动重放。完整计划的确认沿原 DAG 继续，确认后继续使用服务端结果播报，不恢复模型播报循环。

使用实际浏览器点击、生产构建和隔离 `prisma/complete-plan-browser-*.db`。临时本地代理区分受控缺步响应与真实 DeepSeek 上游，两者分别验证；没有通过调用银行写 API 替代前端点击。

## 边界

步骤识别采用有限中文命令、顺序/连接表达和显式数值，不是任意自然语言的完备解析；省略对象、推导金额、跨回合隐含步骤和未识别能力仍需澄清。外部模型可继续故障；本次不代表多实例压力、跨浏览器或全部业务重新验收。开发库、备份及 `.env.local` 未修改，测试服务在验收后关闭。
