# 附加否定与赎回计划验收

基线：`110e20a`。修改、验证和提交均在 `genesis/agent_841944ee` 完成。

## 修复范围

1. 原步骤识别只要看到“不要”等词就删除整段，导致“先给张伟转100.17元但不要重复扣款，再给王芳转200.29元”只剩第二步。现在按已支持的业务动词与否定位置处理：动词前的否定排除该操作，动词后的附加要求保留正向步骤，并截去附加部分，避免其中的金额或对象为该操作背书。结果条件里的“转账失败时”按既有操作引用处理。
2. 原实体映射有产品而无持仓，完整赎回计划使用合法 `holdingId` 仍被判为缺步骤。现在在计划创建前用本人资源解析器规范化赎回节点，并要求当前有效且能唯一定位的持仓；覆盖和顺序检查绑定实际持仓及其产品。不能用模型附带的 `productId` 为另一个持仓背书。历史执行结果恢复路径不变。

修改位于 `lib/request-steps.ts`、`lib/request-constraints.ts`、`agent/tools/planning.ts`。无 schema 或依赖变更；确认、MFA、执行时所有权和报价校验继续生效。
